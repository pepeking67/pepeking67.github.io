# Markov Decision Process (MDP)
![](notion-file-block://4800ad69-a5f8-82a5-b74b-015159e69a8f/25744010-43fa-464e-a9aa-a5d0aa0e78aa?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
classical 강화학습은 MDP를 따른다
agent, environment, state, action, reward로 구성되어 있다
<empty-block/>
## Markov Property
Given the present state, the future and the past are independent
action outcomes depend only on the current state
next state depends on the action and the current state
past action과 state는 미래의 일에는 영향이 없다고 가정한다
<empty-block/>
![](notion-file-block://b8f0ad69-a5f8-832a-a549-019fdbd7fc4c/9f100420-62e0-4eca-ace9-ae3f5cc939f1?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
<empty-block/>
<empty-block/>
action에 확률을 부여 ← stochastic ↔ deterministic
<empty-block/>
MDP는 \<S, A, T, R, $`\gamma`$\>로 표현할 수 있다
S: set of states
A: set of actions
T: state transition probability matrix $`T^a_{ss'}=p(S_{t+1}=s'|S_t=s,\ A_t=a)`$ ← dynamic
T(S, A, \*)들의 합은 1이다
R: reward function $`R^a_s=E[R_{t+1}|S_t=s,\ A_t=a]`$
<empty-block/>
## The Goal of RL
deterministic의 경우 optimal plan(seq of actions) from start to goal
MDP의 경우 optimal policy를 구하는 것을 목표로 한다 $`\pi^*:S\rightarrow A`$
policy는 각 state에 대한 action을 부여한다
optimal policy는 expected utility를 최대화하는 것이다 (reward 최대화가 아님)
<empty-block/>
## Discounting Rewards
cumulative reward: $`R_t=r_t+r_{t+1}+...+r_n`$
discounted cumulative reward: $`R_t=r_t+\gamma r_{t+1}+\gamma ^2r_{t+2}+...+\gamma^{n-t}r_n`$
discount factor $`\gamma`$는 0\~1 사이의 값으로 현재의 보상이 미래의 보상보다 더 가치 있게 만든다
<empty-block/>
![](notion-file-block://7870ad69-a5f8-8399-8b4e-81abf41ea29c/710d2b5c-79a8-40d5-8e24-14fbbdd9dcf2?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
terminal point 이외의 부분에서의 reward를 위의 R(s) 값으로 설정했을 때 값이 클수록 천천히 end point로 가고 값이 작을수록 end point가 음수이든 양수이든 상관없이 빠르게 끝내려 한다
<empty-block/>
RL은 reward를 최대화하는 게 아니라 utility를 최대화하는 것이다
immediate reward + sum of the long term rewards
![](notion-file-block://18e0ad69-a5f8-82d3-9f49-81979d78f143/d942fc29-2750-4a33-a513-7aec097463a1?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
← Bellman optimality equation
<empty-block/>
## How to determine the optimal policy?
Find a strategy with lower probability not to complete a task
![](notion-file-block://7dd0ad69-a5f8-8252-8346-01b0fde344c7/7b397b0b-9f86-489c-8c91-bc8fae8c70c7?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
여기서 보면 가운데로 가는 것은 제대로 못 끝낼 가능성이 높기 때문에 돌들을 피해서 가는 것을 선호한다
<empty-block/>
### Value (utility) function
reward function과 다르게 value function은 long-term value of state s를 부여한다
1. **state-value(**$`V_\pi(s))`$**: **expected return from state s and then following policy $`\pi`$

1. **action-value(**$`Q_\pi(s,a)`$**): **expected return from state s, taking action a, and then following policy 
![](notion-file-block://4f20ad69-a5f8-8316-a911-0137915edbc2/a0d85e08-d6b5-47af-b5f4-95dc73a3654a?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
(Q(s,a)임)
<empty-block/>

<empty-block/>
### Why useing policy?
policy $`\pi`$ is a distribution ofver actions given states
$`\pi(a|s)=P[A_t=a|S_t=s]`$
<empty-block/>
policy는 각 state에 대해 어떤 action을 행할 지를 명시한다
current state에 의존한다 not the history ⇒ policies are stationaty(time-independent)
stochastic의 경우 잘못 갈 수도 있는데 이 때 각 state마다 행동을 부여하면(policy) 다시 복귀하기가 수월함

### Bellman Optimality Equation
![](notion-file-block://9b00ad69-a5f8-822b-b7a9-812dabf2e0cf/b04b5965-7c31-4d15-9954-a8c56f81401a?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
The value of a state under an optimal policy must equal the expected return for the best action from that state
<empty-block/>
1. optimal state-value function: $`V_*(s)=max_\pi V_\pi(s)`$
2. optimal action-value function: $`Q_*(s,a)=max_\pi Q_\pi(s,a)`$
$`Q_*(s,a)=E[R_{t+1}+\gamma V_*(S_{t+1})|S_t=s,A_t=a]`$
<empty-block/>
## How to find an optimal policy?
Planning: exhaustive search, dynamic programming ← 지금 하려는 게 이거임
Reinforcement learning: Monte Carlo method, TD method
<empty-block/>
### Dynamic Programming
1. Optimal substructure: 하위 문제의 최적해를 기반으로 상위 문제를 해결할 수 있다
2. Overlapping subproblems: 하위 문제의 해를 저장했다가 다시 사용할 수 있다
위 두가지를 만족해야 DP를 적용할 수 있다
<empty-block/>
MDP의 경우 Bellman equation이 recursive decomposition, value function이 solution을 저장하고 reuse할 수 있기 때문에 DP를 적용할 수 있다
<empty-block/>
## 1. Value Iteration
1. 각 state의 utility를 계산한다
2. state utility를 사용해서 각 state의 optimal action을 구한다
<empty-block/>
Bellman optimality equation를 통해 value iteration을 진행한다
Bellman optimality eq: $`V_*(s) = \max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V_*(s') \right]`$
이를 통해 VI를 구현하면 $`V_{k+1}(s) \gets \max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V_k(s') \right]`$
VI는 fixed-point solution method이기 때문에 수렴하는 해가 있다
<empty-block/>
1. $`V_0(s)=0`$
2. $`V_{k+1}(s) \gets \max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V_k(s') \right]`$
3. 수렴할 때까지 위 과정 반복
<empty-block/>
이 알고리즘의 시간 복잡도는 $`O(S^2A)`$이다
<empty-block/>
예)
![](notion-file-block://2f30ad69-a5f8-829a-a8f6-01992e6b8ae4/bdb9a8bf-c355-4479-ba98-713eff777601?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=SmartSelect_20241117_172954_Samsung_Notes.jpg)
$`V_{k+1}(s) \gets \max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V_k(s') \right]`$
표시된 부분 $`V_2((3,3))`$를 계산하고자 한다
$`V_2((3,3))=\sum_{s'\in S}P(s'|(3,3),right)[R((3,3),right)+0.9V_1(s')]\\ \quad \quad \quad \quad \ = 0.8[0+0.9*1]+0.1[0+0.9*0]+0.1[0+0.9*0]=0.72`$
<empty-block/>
이를 수렴할 때까지 혹은 threshold까지 반복하여 $`V_*`$를 구한다
<empty-block/>
이후 optimal policy를 구하려면 다음을 계산한다
$`\pi^*(s) = \arg\max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V(s') \right]`$
<empty-block/>
VI의 문제점은 시간 복잡도가 $`O(S^2A)`$로 매우 크다
<empty-block/>
## 2. Policy Iteration
1. Policy evaluation: calculate utilities for some fixed policy(not optimal) until convergence
2. Policy improvement: update policy
<empty-block/>
policy evaluation 과정:
![](notion-file-block://1460ad69-a5f8-8387-9b58-01572847c97d/4eee8d70-0c93-44e8-952f-bff78f748084?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
fixed policy에 대해서 value가 수렴할 때까지 단순히 Bellman updates를 적용한다
이 경우에 Bellman equation은 linear system이고 max operator를 사용하지 않기 때문에 $`O(n^3)`$ 시간이 걸린다
iteration 마다 $`O(S^2)`$이 걸린다
<empty-block/>
policy improvement 과정:
위에서 얻은 fixed utility value를 통해 one-step look-ahead 방식을 통해 더 좋은 plicy가 있는지 확인한다 ⇒ policy extraction
$`\pi_{i+1}(s) = \arg\max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V^{\pi_i}(s') \right]`$
<empty-block/>
VI와 PI 모두 optimal values를 계산한다
PI가 시간이 덜 걸린다
<empty-block/>
# Reignforcement Learning
Goal: optimal way to make decisions
delayed reward: decisions now can impact things much later 
ex) 시험 공부하면 나중에 시험에서 잘 본다
⇒ 두 가지 challenge가 있다
- Planning: decisions은 immediate benefit 뿐만 아니라 longer-term consequences를 포함한다
- Learning: temporal credit assignment is hard = 어떤 요소가 나중에 high or low rewards를 주는지 알기 힘들다
<empty-block/>
selecting action을 할 때 2가지 방식이 있다
- exploitation: make the best decision given current info, risk of missing out on a better reward somewhere else
- exploration: gather more information, risk of wasting time & getting negative reward
<empty-block/>
RL의 mapping from past experiences to action이 policy이다
generalization이 필요한데 일부 states만 과거에 관찰될 수도 있고, 관찰되지 않은 states에 대해서도 일반화할 필요가 있다
<empty-block/>
## Monte-Carlo Methods (MC)
trial-and-error approach
complete knowledge를 가정하지 않는다
experience → values, policy
<empty-block/>
몬테 카를로 방식은 다음 두 가지 방식으로 사용될 수 있다
1. model-free: 환경의 명시적인 모델 (전이 확률, 보상 함수)를 몰라도 최적 정책을 학습할 수 있다
2. simulated: 시뮬레이션으로 학습을 진행할 수 있다
<empty-block/>
하나의 에피소드가 끝난 뒤에 complete sample returns를 통해 학습을 진행한다
episodic 기반의 문제에만 적용할 수 있다
<empty-block/>
Goal: policy $`\pi`$에서의 episodes of experience로부터 V, Q를 학습한다
하나의 에피소드에서의 return 을 보면 total discounted reward 형태이다
![](notion-file-block://3560ad69-a5f8-8398-b4a5-012a307aafd3/1cea9d38-f0a3-4d93-8560-a5f94ae75cc5?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
MDP에서 value function은 expected return으로 정의된다
![](notion-file-block://7590ad69-a5f8-83f2-9788-81f03a0a97b8/3c532d35-ad36-4a7a-9f27-5de1fad36651?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
MC에서는 이러한 expected return 대신에 empirical mean return을 사용한다
![](notion-file-block://5de0ad69-a5f8-83e9-9840-01a688c32dd1/b7b3bc78-0dc8-4869-8177-d8cc05cc6561?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
G(S1)=R1+$`\gamma`$R2+…=R1+$`\gamma`$G(S2) 이런 식으로 계산됨
<empty-block/>
![](notion-file-block://6cc0ad69-a5f8-82d9-9946-816cabcc1288/88996429-ef54-48ef-9b81-b05e32b0a4ea?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
<empty-block/>
### Incremental MC updates
Goal: update V incrementally after episode S1, A1, R2, …, ST
추가적인 에피소드를 통해 얻은 return G를 현재의 value에 적용하는 방식이다
계산의 효율성을 위해 처음부터 다시 평균을 계산하지 않고 다음과 같은 방식을 사용한다
![](notion-file-block://b8a0ad69-a5f8-839f-b609-8108c7e69ebd/ca4dce91-484b-4b56-9195-bb91a966009c?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
비정상적인 상황에서는 과거의 데이터를 가지고 평균을 계산하는 것이 오히려 안 좋기 때문에 1/N 부분을 고정된 rate $`\alpha`$로 둬서 running mean에 집중하는 것이다 ⇒ forget old episodes
![](notion-file-block://c6f0ad69-a5f8-8310-87e6-01b0a6067fe4/31389064-bf91-4d11-9162-1f5ee3943dfd?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)

## Temporal-Difference Learning (TD)
MC + DP
learn directly from episodes of experience
model-free → MDP transitions, rewards를 몰라도 된다
learns from incomplete episodes by **bootstrapping**
episodic이 아니여도 된다
<empty-block/>
Goal: learn $`V_\pi`$ online from experience under polcy $`\pi`$
<empty-block/>
- incremental every-visit MC: update value V toward **actual** return G
![](notion-file-block://ab90ad69-a5f8-83f5-bddc-814953ca81f6/7f5f55ce-711b-4904-a34b-b03810228d1e?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
- simplest TD learning algorithm TD(0): update value V toward **estimated** return 
![](notion-file-block://4fd0ad69-a5f8-82ec-adef-01764ad0555e/00f2db4f-8d2f-4322-a03e-10786464d837?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
부트스트래핑: using one or more estimated and same type of values during the update
<empty-block/>
![](notion-file-block://fa80ad69-a5f8-8296-8100-818716d8192a/fa095191-5304-4c73-8453-8702163b33ae?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
TD에서 V나 Q를 업데이트 하는데 다음과 같다
![](notion-file-block://1600ad69-a5f8-8262-8b2f-81f0aaf5a2ad/26a24b7c-5e88-44fb-ace5-350b61e33db3?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
이 때 true $`V_\pi`$를 사용하지 않고 current estimate V (⇒ samping)를 사용한다
⇒ 그래서 끝까지 갈 필요 없다 ← bootstrapping
- $`\epsilon`$-greedy: 1-ep 확률로 exploitation, ep 확률로 exploration
<empty-block/>
![](notion-file-block://c960ad69-a5f8-836b-ad52-01357c24c131/8e472570-62b1-4a39-9a05-b08604c1f014?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
<empty-block/>
MC의 경우 end of episode의 return을 알 때까지 기다려야 한다는 단점이 있다
TD의 경우 매 step마다 learn online할 수 있다
<empty-block/>
TD는 final outcome이 없어도 학습이 진행된다
TD는 incomplete sequences에서도 진행이 되고 MC는 complete에서만 가능하다
그래서 TD는 continuing (non-terminating) 환경에서도 작동한다 (MC는 불가능)
<empty-block/>

## On/Off policy
on policy: target policy = behavioral policy
⇒ final policy is influenced by the exploration policy
⇒ after policy improvement, cannot reuse experience
<empty-block/>
off policy: target policy != behavioral policy
⇒ final policy is independent of the exploration policy
<empty-block/>
### SARSA
← on policy
learn action-value function Q with TD(0)
use transition (St, At, Rt+1, St+1, At+1) for updates
![](notion-file-block://8070ad69-a5f8-83bb-b049-01924088afaa/e20dc6fe-a55e-4962-b191-6dc8fa35d764?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
policy를 $`Q_\pi`$를 사용해서 greedily하게 바꾼다
(s,a)가 infinitely many times 방문되거나 policy가 greedy policy에 수렴하면 수렴한다
![](notion-file-block://19b0ad69-a5f8-824e-8743-81ef95adf6b5/e82f93dc-aa59-4023-a7fd-fbe1fccc8be1?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
<empty-block/>
### Q-learning
← off policy
Q directly approximates Q\* independent of the behavior policy

## Deep RL
예를 들어 Q-table이 10억개 이런 식으로 데이터가 너무 많을 때에는, DL을 활용할 수 있다
![](notion-file-block://0c90ad69-a5f8-8234-975d-81973bf8cd48/0ae18ac1-8224-44d4-8b15-8bf81a60a2df?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
![](notion-file-block://f6e0ad69-a5f8-8227-be33-01d6f22ef728/0ce08db2-543a-4146-93f2-bd798e791f4b?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
여기서 문제가 Q가 지속적으로 업데이트 되기 때문에 타겟이 고정되지 않는다 (non-stationary)
prediction을 타겟값에 맞추기 위해 학습이 진행되는데 타겟값이 변해서 불안정해짐
⇒ moving Q-targets
We move the prediction to the target, but we also move the target. → High divergence
이러한 oscillation을 방지하기 위해서 target network를 한 번 더 업데이트 한다
![](notion-file-block://5cb0ad69-a5f8-8202-b081-8194be652453/b85d821c-e284-4d8d-a512-b7af0b4facbb?space_id=a572f2a2-f7b0-4923-b5c0-74f5db67bcd1&name=image.png)
이 손실함수를 통해 prediction과 타겟값의 차이를 줄이는 방향으로 학습할 수 있다
