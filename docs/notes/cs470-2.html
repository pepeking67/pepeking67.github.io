Deep Learning - Perceptrons

binary classification task에 대해서 데이터들을 linearly하게 separate하고자 한다. 1. input: a sequence of training data 2. initialization: randomly initialize weights 3. learning rule: classify with the current weights, and then if wrong adjust the weight vector by adding or subtracting the feature vector ex) 여기서 식을 보면 y(실제값)과 h값이 같으면 w에 변화가 없고 다르면 변화가 생긴다.

Properties of Perceptrons

  1. Separability: true if some parameters get the training set perfectly correct
  2. Convergence: if the training set separable, perceptron will eventually converge
  3. Mistake Bound: the maximum # of mistakes related to the margin or degree of separability

이 때 문제는 데이터가 linearly하게 separable하지 않는다면 노이즈가 발생한다. threshold function을 사용하면 기능을 향상시킬 수 있지만 여전히 선형적이다. ouput을 좀 더 soften하게 만들 필요가 있다.

참고) 왜 ReLU를 많이 사용하는가? 기존에는 시그모이드 함수를 많이 사용했었는데 시그모이드 함수의 기울기가 0부터 1 사이이기 때문에 기울기 소실(vanishing gradient) 문제가 발생한다. 그래서 이를 보완하기 위해 ReLU를 도입한 것이다. ReLU는 음수값을 0으로 반환하기 때문에 특정 양수로 수렴하지 않아서 이러한 기울기 소실 문제가 발생하지 않는다. ReLU 이전의 함수는 활성화 함수가 부드러워야 더 학습이 잘된다고 생각했기 때문에 보통 exp 함수를 많이 사용했고 그러다 보니 경사하강법을 쓸 때 학습 속도가 매우 느렸다. ReLU는 함수의 형태가 간단하기 때문에 학습 속도가 매우 빠르다. 하지만 데이터가 음수일 때 값이 0으로 반환되어서 업데이트가 되지 않는 문제가 있다(Dying ReLU) 또한 ReLU 함수는 0에서 미분 불가능하다는 문제도 있다. logistic(sigmoid) 함수를 보면 위의 참고에서 말했듯이 기울기가 0으로 수렴한다. 그래서 여기서는 업데이트에 실패하게 된다.

너무 많은 epochs를 학습시키는 것은 over train될 수 있다 모든 epoch 이후에 hold-out validation set과 test accuracy를 유지한다 validation set에 대한 가장 좋은 성능의 네트워크 가중치를 저장하고 성능이 저하되면 다시 되돌린다

k-fold cross-validation: determine the average number of epochs that optimizes validation performance 데이터를 k개로 나눈 후 k-1개를 학습용 데이터, 1개를 테스트용 데이터로 사용한다. 이렇게 해서 총 k개의 성능 지표를 얻는다

Dropout training

During training, for each step, decide whether to delete a hidden unit with some probability p ⇒ make predictions using only a randomly chosen set of neurons, update only these neurons

너무 적은 양의 hidden unit이면 정확한 학습이 불가능하다 너무 많으면 오버피팅이 일어난다 similar cross-validation method를 통해서 적절한 양의 hidden unit의 개수를 정할 수 있다

Convolution Neuron Net(CNN)

→ smaller network fully connected model에서 모든 edge가 필요하지 않다 - Locality: Some patterns are much smaller than the whole image ⇒ can represent a small region with fewer parameters - Translation invariance: Same pattern appears in different places → they can be compressed - Subsampling: Subsampling pixels will not change the object

⇒ fewer parameters to characterize the image

Convolutional Layer: has a number of filters that does convolutional operation 각 필터는 small pattern을 감지한다 예를 들어 여기서 필터는 대각 요소를 추출하는데 convolution 값을 통해 가장 큰 값을 가지는 애가 대각 요소로 이루어진 것을 확인할 수 있다

필터가 여러 개면 n * 4 * 4 형태로 feature map이 만들어진다 color image의 경우 채널이 3개이기 때문에 3 * m * m 형태이다

Convolution vs Fully connected

CNN: feature map 2 * 4 * 4 = 32, filter 2 * 3 * 3 = 18 ⇒ 50 parameters Fully connected: 36 * 2 = 72 parameters (weights의 개수)

CNN 과정

Pooling Layer

reduces input dimensions to save computation and improve feature detector’s positional invariance (입력 이미지가 조금 달라져도 잘 인식할 수 있게 함) max pooling, average pooling 등이 있다

convoluton과 pooling 이후의 결과로 나오는 feature map의 채널의 개수는 filter의 개수와 같다 input의 경우 흑백이면 채널이 1, 컬러면 3이다

CNN in PyTorch

self.conv1 = nn.Conv2d(3,6,5) ← (# input, # filter, filter size=5*5) ⇒ there are 6 5*5 filters self.pool = nn.MaxPool2d(2,2) ← (2*2 window, stride) *stride: 움직이는 거리 self.conv2 = nn.Conv2d(6,16,5) ← 첫 번째 convolutional layer의 필터 개수가 6개여서 여기서는 6개의 채널임 self.pool = nn.MaxPool2d(2,2) 첫 번째 convolutional layer에서의 파라미터 개수: 각 필터의 파라미터 개수 = 3 * 25 (채널이 3이기에 각 필터는 3 * 5 * 5 크기를 가진다) 총 파라미터 개수 = 75 * 6 = 450

두 번째 convolutional later의 파라미터 개수: 각 필터의 파라미터 개수 = 6 * 25 총 파라미터 개수 = 150 * 16 = 2400

이후에 x = torch.flatten(x, 1) # 평탄화 x = F.relu(self.fc1(x)) # fully connected feedforward network x = F.relu(self.fc2(x)) x = self.fc3(x) 를 통해 output을 구한다

CNN은 음성(파동 이미지를 CNN 분석)이나 텍스트(sentence matrix에 CNN 적용) 데이터에 대해서도 적용할 수 있다
