Optimality of A* Search (Proof)

Suppose sub-optimal goal B is on the fringe(테두리) some ancestor n of A is on the fringe too Claim: n will be expanded before B

f(n)=g(n)+h(n)f(n)≤g(A)g(A)=f(A)g(A)<g(B)f(A)<f(B)f(n)=g(n)+h(n)\\f(n)\leq g(A)\\g(A)=f(A)\\ \\g(A)<g(B)\\f(A)<f(B)f(n)=g(n)+h(n)f(n)≤g(A)g(A)=f(A)g(A)<g(B)f(A)<f(B)

  1. f(n) ≤ f(A)
  2. f(A) < f(B)
  3. n expands before B ← f(n) ≤ f(A) < f(B) ⇒ all ancestors of A expand before B ⇒ A expands before B ⇒ A* search is optimal

Constraint satisfaction problems (CSPs)

constraint satisfaction: method where each variables has a value that satisfies all the constraints on the variable

3 components 1. X: set of variable {X1, …, Xn} 2. D: set of domains {D1, …, Dn}, one for each variable 3. C: set of consraints

solution ⇒ complete variable assignment that is consistent (satisfies all the given constraints) key idea: constraint를 사용해서 search space에서 탐색할 영역을 줄이고 general inference algorithms과 연관된 representation language를 사용한다 ← heuristic처럼 특정 문제에만 적용되지 않고 일반적인 상황에서도 해결할 수 있도록 한다

Assignment: values to variables

X: variables, v: values values를 variables에 assignment한다 1. consistent/legal: not violate constraints 2. complete: every variable is assigned a value 3. partial: some variables unassigned

Constraint: scope and relation

scope: tuple of variables that participate in the constraint rel: relation that defines the values that those variables can take on 1은 implicit, 2는 explicit하게 나타낸 것이다

Constraint Graph

binary CSP: each constraint relates two variables (at most) binary constraint graph: nodes → variables, arc → constraints

위 MRV heuristic은 첫번째 variable을 선택할 때에는 도움이 되지 않는다 ⇒ degree heuristic select variable in the largest # of constraints on other unassigned variables → reduces branching factor (이 variable의 value는 다른 애들의 가능한 value들을 줄이기 때문)

Ordering values

표시된 부분에 해당하는 과정이다

least constrained value ⇒ leave maximum flexibility for subsequent assignments 가장 가능할 거 같은 solution을 체크하게 된다 → 실패를 미룸

Inference/Filtering: Forward checking

basic idea: track domains for unassigned variables and eliminate values that violate constraints with existing assignments

forward checking: variable X가 assigned 되면 unassigned variable Y connected to X를 constraint를 통해 확인한다. Y에서 X의 value와 inconsistent한 value를 지운다

Arc consistency

directed arc X → Y is consistent iff ∀x of X,∃y of Y s.t. (x,y) satisfies the constraint btw X and Y\forall x \ of \ X, \exist y \ of\ Y \ s.t.\ (x,y)\ \text{satisfies the constraint btw X and Y}∀x of X,∃y of Y s.t. (x,y) satisfies the constraint btw X and Y

remove values from the domain of X to enforce arc-consistency arc consistency detects failures earlier

이 방식은 forward checking보다 1 step 빠르게 확인하기 때문에 빠르다 domain of variable이 없어지면 backtrack한다

arc consistency는 pairwise arcs는 consistent하지만 CSP가 consistent하지 않을 수도 있다는 문제가 있다

K-consistency는 k개의 변수 사이에서 consistency가 만족되는 경우를 뜻한다 1 \~ k-1 consistency를 가지면 strong k-consistnecy를 가진다고 말한다

Knowledge and Reasoning

Knowledge-based Agent (KBA)

knowledge-based agent가 reasoning을 통해 complex task를 수행한다 knowledge-based agent: uses prior or acquired knowledge to achieve goals ⇒ can make more efficient and informed decisions

knowledge base (KB): agent의 환경의 facts에 대한 representations들의 집합이다 knowledge representation language를 사용해서 tell what to know, ask agent to query what to do ⇒ telled facts를 통해 agent는 deduce new fact할 수 있다

axiom: sentence not derived from other sentences declarative approach ⇒ add new sentences: tell it what it needs to know ⇒ query what is known: ask itself what to do ← knowledge based agent (KBA)

example: Wumpus World

logics: formal languages for representing information ← 결론을 내릴 수 있어야 함 ex) x < 이거 자체는 logic이 될 수 없음. x < y 이런 식으로 완전하게 구성되어야 함 syntax: defines the sentences in the language semantics: define the meaning of sentences

Entailment

one thing follows from another

KB⊨αKB\models \alphaKB⊨α

KB entails sentence α\alphaα ↔ α\alphaα is true in all worlds where KB is true 이 개념은 한국어로 함의라고 한다 ex) KB containing ‘the Giants won’ and ‘the Reds won’ entails ‘either the Giants won or the Reds won’ no breeze in [1,1] entails no pit in [1,2], [2,1]

entailment는 semantics를 기반으로 한 relationship btw sentences (⇒ syntax) ⇒ entailment is different than inference

Models

model이란 truth가 evaluated될 수 있는 structured world이다 If α\alphaα is true in m, then m is a model of a sentence M(α\alphaα) is the set of all models of α\alphaα Then KB⊨αKB \models \alphaKB⊨α iff M(KB)⊆M(α)M(KB)\sube M(\alpha)M(KB)⊆M(α)

Inference

KB⊢iαKB \vdash_i\alphaKB⊢i​α ⇒ sentence α\alphaα can be dereived from KB by procedure i 1. soundness: i is sound if whenever KB⊢iαKB \vdash_i\alphaKB⊢i​α, it is also true KB⊨αKB \models \alphaKB⊨α 구조론적으로 참일 때 의미론적으로도 참이면 sound하다라고 한다 1. completeness: i is complete if whenever KB⊨αKB\models \alphaKB⊨α, it is also true KB⊢iαKB\vdash_i\alphaKB⊢i​α 참인 명제는 논리적으로 참이라고 증명할 수 있다 epistemological은 possible state

Propositional Logic

declarative sentence (fact)는 true or false로 구분할 수 있다 P가 well formed formula라고 가정한다 ⇒ not P가 unknown인 경우 제외 ⇒ T/F만 고려 Modus Tollens: p→q, not q then not p 이렇게 truth table을 그려보면 두 명제가 true일 때 결론도 true이기 때문에 valid하다

이런 식으로 문제 상황을 나타낼 수 있다

그러나 이런 propositional logic은 too weak하다 each rule has to be represented for each situation cannot keep track of changes ⇒ huge rule-base inference에는 적합하지 않다

First-Order Logic (FOL)

propositional logic은 world가 facts들을 contain한다고 가정했다면 FOL은 (predicate logic) objects, predicates, functions, variables를 가진다고 가정한다 object ← constant, predicate ← relation functions are relations with single value for each object

Atomic sentence = predicate(term1, …, term_n) or term1 = term2 ⇒ return T/F Term = function(term1, …, term_n or constant or variable ⇒ return values

atomic sentences를 connectives를 통해 complex하게 만든다

Problems

  1. Frame problem ← 상태가 변할 떄 변하지 않는 요소들을 어떻게 표현할 것인가
  2. Qualification problem ← action이 성공하기 위한 모든 조건들을 정의할 수 없다 (너무 많다)
  3. Ramification problem ← (파생 효과 문제) action들의 파생 효과들을 어떻게 처리할 것인가

linear planning: work on o e goal until completely solved before moving on to the next goal ⇒ maintains goal stack

STRIPS

Stanford Research Institute Problem Solver way of representing actions action(operator)는 다음 3가지 parts로 구성된다 1. PC: list of action preconditions 2. A: list of action add effects 3. D: list of action delete effects

At(Home)→go(outside)¬At(Home)\text{At(Home)} \xrightarrow{\text{go(outside)}} \neg \text{At(Home)}At(Home)go(outside)​¬At(Home)

pickup(x) ← STRIPS operator particular instance pickup(a) ← action

이런 식으로 STRIPS가 진행된다 이를 통해 최종적으로 plan을 만들 수 있다

STRIPS가 problem들을 해결하는가? 1. Frame → yes 2. Ramification → no, ground fact만 사용 3. planning method → linear search ← 어떻게 평가할 수 있는가?

sussman anomaly: move(A,Table,B) → move(A,B,Table) 이런 식으로 동일한 상황이 되도록 계획되는 경우가 발생함

STRIPS planner is sound and suboptimal STRIPS operators are not very expressive

classical planning task를 위한 standard encoding language이다 PDDL은 시스템을 preconditions와 post-conditions를 통해서 표현한다 (PDDL includes FOL)

components) objects, predicates, initial state, goal specification, actions/operators

PDDL로 문제를 정의할 때 다음 2가지 정의를 사용한다 1. Domain definition → domain predicates, operators(actions) 2. Problem definition → objects, initial state, goal

requirements → packages to be used types, constants, predicates, action 으로 구성된다

preconditions: operator 적용 전에 predicate가 true effects: operator 적용 후에 predicate가 true 이 예시에서 보면 type을 사용하기 위해서는 requirements에 [:typing]을 추가해야 한다

PDDL에서는 ?x - int 이런 식으로 변수와 타입 설정을 한다 데이터 타입이 predefined되지 않는다 parameter나 action의 variables로 쓰일 때 type을 명시해야 한다

predicate는 object(?things)의 T/F property(yellow)를 정의한다

not, and, or과 같은 conjunction을 사용할 수 있는데 이를 위해서는 requirements :strips를 사용 ex) (and(Yellow Box) (not (Yellow Tray))

precondition: action이 적용될 수 있는 state of the system effect: action을 적용한 후의 state

strips domain은 and밖에 못 쓰지만 adl(action description language)는 and not or forall exists들을 쓸 수 있어서 좀 더 expressive하다 ← requirements :strips/:adl
